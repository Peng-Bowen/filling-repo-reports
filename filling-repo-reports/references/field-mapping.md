# 字段映射与计算规则

## 必需配置

开始填写前取得并记录：

| 配置 | 要求 |
|---|---|
| product_name | 产品全称 |
| product_short | 内部确认的产品简称 |
| issuer_code | 发行机构代码 |
| positive_prefix | 正回购编码前缀 |
| reverse_prefix | 逆回购编码前缀 |
| currency_value | 模板要求的币种落盘值 |
| rate_storage_mode | 数值、不带百分号文本、带百分号文本或 Excel 百分比 |
| interest_basis | 计息基础代码 |
| collateral_type | 回购标的类别 |
| market_map | 执行市场/托管市场到模板枚举的映射 |
| counterparty_types | 带生效日期的对手方类型字典 |
| exchange_fallback | 匿名交易所回购的对手方和备注规则 |
| tolerance | 金额勾稽允许差额 |

历史文件中可能同时存在 ZHG/NHG、人民币/CNY、带百分号文本/不带百分号数值等不同口径。不能根据旧文件静默选择，必须使用当期配置。

## 数据源优先级

1. 估值表决定期末是否存在、账面净价和分类控制数。
2. 回购到期浏览表提供分笔方向、起止日期、报告日应计利息，以及用于存续识别和交叉核对的融入资金/融出资金。
3. 交易查询提供状态、方向、日期、利率、费用、市场、对手方、外部成交编号和 AJ“回购标的金额”的直接来源“结算金额（元）”。
4. 静态参数和字典提供报送代码与格式。

## 跨表匹配

不要只按 R001、R007、GC001 等回购代码匹配。优先组合：

> 回购代码或协议编号  
> ＋交易方向  
> ＋交易日期  
> ＋到期日期  
> ＋交易本金  
> ＋对手方（如有）

匹配顺序：

1. 日期、到期日、本金和方向；
2. 回购代码、执行市场和托管市场；
3. 对手方和外部成交编号；
4. 协议回购使用到期表或估值表中的完整协议编号。

候选不是唯一值时停止，不按行距、金额接近或历史顺序猜测。

## 金额公式

### 净价

估值表有单笔账面明细时，直接取该笔报告日账面值。

只有估值表按同代码汇总、确实需要拆分时，才使用：

> 正回购分笔净价 = 结算金额－交易费用－结算费用  
> 逆回购分笔净价 = 结算金额＋交易费用＋结算费用

方向原因：

- 正回购形成负债，费用从融入资金中扣减；
- 逆回购形成资产，费用计入买入返售资产成本。

分笔净价之和必须分别等于估值表卖出回购或买入返售控制数。

### 报告日应计利息

> 正回购应计利息 = 回购到期表“应计利息（付）”  
> 逆回购应计利息 = 回购到期表“应计利息（收）”

再与估值表对应应计利息科目核对。

绝不使用完整期间的应收收益、应付收益或到期还款金额推导报告日应计利息。即使某个短期样本碰巧相等，也不能推广。

### 全价、数量和回购标的金额

> 全价市值 = 净价市值＋报告日应计利息  
> 委外资产明细数量 = 净价市值  
> 回购标的金额 = 交易查询“结算金额（元）”

到期还款金额只用于合理性检查，不是报告日全价来源。

回购到期浏览表的“融入资金/融出资金”用于：

- 判断正回购或逆回购是否存在有效本金；
- 建立报告日存续头寸；
- 与交易查询“结算金额（元）”交叉核对；
- 辅助唯一匹配交易。

回购到期浏览表中的“融入资金/融出资金”不作为回购标的金额的直接填写来源。两者不一致时记录源文件、源行、两个金额和差异，但不得用融入资金或融出资金覆盖结算金额。

如果结算金额缺失、为 0，或差异导致交易无法唯一匹配，停止该笔填报并提交复核。

### 费用方向示例

假设结算金额为 1,000,000，交易费用为 10，结算费用为 20：

- 正回购净价为 999,970；
- 逆回购净价为 1,000,030。

## 年利率

来源为交易查询“回购利率(%)”。先还原业务数值，再按 rate_storage_mode 写入：

| 模式 | 业务利率为百分之一点七时的落盘方式 |
|---|---|
| number | 数值 1.7000 |
| text-percent | 文本 1.7000% |
| excel-percent | 数值 0.017，并设置百分比显示格式 |

模板和配置未明确时停止，不根据单元格右对齐或界面显示猜测底层类型。

## 资产编码

编码前缀按交易方向固定映射：`ZHG` = 正回购（质押式正回购/融资回购），`NHG` = 逆回购（质押式逆回购/融券回购）。不得将正回购前缀套用于逆回购，也不得根据历史产品文件静默推断。

正回购：

> 正回购前缀-产品简称-资产代码-YYYYMMDD

逆回购：

> 逆回购前缀-产品简称-资产代码-YYYYMMDD

同方向、同代码、同报告日有多笔时增加顺序号。同组内按起息日、到期日、源文件行号排序。不同代码的整体顺序使用配置；没有配置时建议先正回购、后逆回购，各组按估值表明细顺序。

两份报表必须使用相同编码和相同排列顺序。编码按文本写入。

## 委外资产明细

| 列 | 字段 | 规则 |
|---|---|---|
| A | 所属资管计划名称 | product_name |
| B | 资产代码 | 生成的唯一编码 |
| C | 底层资产/负债编码 | 回购业务与 B 一致 |
| D | 资产名称 | 估值表科目名称优先；协议回购使用规范名称加完整协议编号 |
| E | 全价市值 | 净价加报告日应计利息 |
| F | 净价市值 | 估值表单笔值或经控制数验证的拆分值 |
| G | 数量 | 等于净价市值 |
| H～L | 其他字段 | 按当前模板和数据元规范；不得从旧文件静默沿用空白 |

金额写为数值，编码写为文本，不覆盖模板说明。

## 资产要素登记

### 公共信息

| 列 | 字段 | 规则 |
|---|---|---|
| A | 行内资产/负债编码 | 与委外表 B、C 一致 |
| B | 发行机构代码 | issuer_code |
| C | 资产/负债类别 | 正回购按卖出回购代码；逆回购统一填 `1108 债券买入返售` |
| D | 交易流通场所 | market_map |
| E | 币种 | currency_value |
| F、G | 风险五级分类、资产流动性 | 仅逆回购填写：F=`01 正常`，G=`03 其他`；正回购留空 |

### 回购信息

| 列 | 字段 | 规则 |
|---|---|---|
| AC | 起息日 | 交易日期；用到期浏览表复核 |
| AD | 到期日 | 到期结算日期；必须晚于报告日 |
| AE | 对手方 | 交易查询对手方全称；匿名交易所回购按 exchange_fallback |
| AF | 对手方类型 | 报告日有效的 counterparty_types |
| AG | 年利率 | 按 rate_storage_mode |
| AH | 计息基础 | interest_basis |
| AI | 回购标的类别 | collateral_type |
| AJ | 回购标的金额 | 直接取交易查询“结算金额（元）”；融入资金/融出资金只作交叉核对 |
| JW | 备注 | exchange_fallback 或当期报送规则 |

## 写入要求

- 先渲染并检查模板格式；
- 只写目标单元格的值，保留工作表、合并、验证和格式；
- 只选择性粘贴数值，不整行覆盖；
- 输出到新文件，不覆盖模板；
- 超长协议编号不得变成科学计数法；
- 保存后重新打开并检查日期、金额、利率和编码。
